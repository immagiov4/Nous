# Asset adoption and cleanup

Lesson generation can write an image and fail before saving the lesson that would use it. Deleting every file from a failed run would also be unsafe if a supported path had already adopted one. Nous tracks provisional ownership separately from committed project references so cleanup can distinguish abandoned output from retained course material.

## Adopt output at the project boundary

While preparation runs, its provisional owner accounts for the file. Adoption connects the generated bytes to a committed lesson reference; cleanup must check live references before removing abandoned output. The [project services](../../../apps/backend/src/projects/) own these operations.

## Identity includes the source context

Uploaded files already belong to a project, but their identity still constrains access. Identical uploads in separate projects remain separate resources; a content match does not authorize retrieval from another project. Code archives retain their own index for selected-file access under that identity.

An extracted PDF figure carries page and text context from the document that supplied it. If the document changes, that interpretation must change with it: a caption from an earlier PDF could otherwise describe unrelated replacement content. Source replacement refreshes the image context, and reference resolution uses both source artifact and source visual identity. [Ingestion](../03-section-features/03-p-doc-processing.md) explains how those relationships are extracted.

## Restore the files retained content needs

A portable [project archive](../03-section-features/05-p-project-workspace.md) carries saved data and the files needed to restore it. Import checks integrity, converts supported older archive shapes and reconnects image and PDF references to the imported copies. Unmatched references remain available for review instead of being attached to an unrelated file by guesswork.

Playback audio has a different recovery contract because it can be derived again from the saved lesson and selected voice/model. Portable archives exclude that audio, while original sources and lesson visuals retain their bytes. Installation backups have a separately defined scope in [deployment recovery](../08-section-deployment/01-p-self-hosted.md#back-up-and-restore); choose that contract when changing operator backups rather than inferring it from project portability.

## Load course covers

Home and course cover generation share the cover loader. Its first stored-cover read also checks storage availability and supplies that project's cover. Other projects await the availability result before reading their own covers; concurrent requests for one project share the same in-flight operation. Settled covers are read again on later calls.
