## Project shape

- **Project**: the unit of study. One source document (PDF, codebase bundle, or learn-mode) plus its generated learning plan, assets, annotations, and session state.
- **Project snapshot**: the serializable payload of a project. What gets persisted and what hydrates the workspace domain.
- **Workspace**: the part of the frontend that operates on the currently open project: domain, controller, reader state, reader actions.
- **Domain**: the source-of-truth reducer state for the open project (`services/workspace/domain.ts`). Pure, no side effects, knows nothing about screens.
- **Controller**: the layer above the domain that drives user-visible operations (create, open, generate, evaluate). Coordinates AI calls, persistence, and domain mutations. Exposes `WorkspaceControllerStateAdapter`.
- **Workflow**: a tracked asynchronous operation in the controller (assessment, planning, loadSection, generateLesson, etc.). Each workflow carries `status: 'idle' | 'pending' | 'succeeded' | 'failed'` and a monotonically increasing `requestId` so late results from cancelled runs are ignored.
- **Session state**: the transient slice of controller state that resets between projects: `assessmentMessages`, `chatSession`, `openingProjectId`. Cleared by `resetSessionState()`. Distinct from the persisted `ProjectSnapshot` and from `workflowState`.

## Learning plan

- **Learning plan** (`LearningPlan`): the AI-generated study path for one project. A title, a summary, and a list of modules.
- **Module** (`LearningModule`): a top-level chapter of the plan. Contains `children: PathNode[]`.
- **Path node** (`PathNode`): a child of a module. Either a `LessonNode` or an `ApplicationExerciseNode`. Lessons and exercises are interleaved inside the same array.
- **Lesson** (`LessonNode`, `kind: 'lesson'`): a study page. Carries its markdown content, quiz, image refs, annotations, and optional `parentId` for sub-chapters.
- **Sub-chapter**: a lesson with `parentId` pointing to another lesson in the same module. Treated as a child page during navigation.
- **Application exercise** (`ApplicationExerciseNode`, `kind: 'exercise'`): an AI-evaluated exercise intercalated between lessons. Carries a brief, attachments, and feedback.
- **Quiz**: a sequence of `QuizQuestion` entries attached to a lesson. Generated by the lesson markdown quality pipeline.
- **Annotation** (`SectionAnnotation`): a highlight or sticky note anchored to text inside a lesson.

## AI integration

The frontend has two AI infrastructures by design. See `docs/ARCHITECTURE.md#two-ai-clients` for the routing rule.

- **OpenRouter**: the upstream provider. All AI calls go through the backend proxy; the browser never holds the API key.
- **Pipeline**: a coherent batch sequence of one or more AI calls for a single goal (assessment, planning, research, curriculum, lesson generation, lesson verification, lesson markdown quality, lesson images, visual examples, exercise placement, exercise brief, document indexing, TTS). Lives under `services/openrouter/`. Uses `callOpenRouter`.
- **Model slot**: a logical AI call whose model can be overridden by the user via UI preferences. Four slots exist: `lesson`, `assessment`, `context`, `tts`. Other models in `services/openrouter/config.ts` are fixed by env var only.
- **Reasoning**: the model's chain-of-thought, surfaced live via Server-Sent Events when `callOpenRouter` is called with `onReasoningUpdate`.
- **Chat with tool calls**: an interactive AI conversation that can invoke tools to read or modify project data. Built on Vercel AI SDK (`@ai-sdk/react`, `ai`). Two instances exist: the **Ask AI panel** in the Reader and the **Library home chat**.
- **Tool call**: a function the chat AI can invoke (e.g. `listLibraryTree`, `getProjectOverviews`). Executed server-side in the chat routes and locally in `services/library/toolExecutor.ts`.
- **Research dossier** (`ResearchLessonDossier`): per-section research material gathered by the research pipeline (Perplexity-based) before lesson generation. Stored on the domain as `researchDossiersBySectionId`.
- **Research course plan** (`ResearchCoursePlan`): the pre-lesson research output that drives the research-mode planner.
- **Document index** (`PdfTextIndex`): mapping from PDF chunks to pages and plan sections. Built once per project; consulted by the lesson and exercise pipelines.

## Persistence

- **`ProjectRepository`**: the frontend interface for project + library-tree CRUD. Two adapters: `IndexedDbProjectRepository` (browser-local) and `HttpProjectRepository` (LAN). Selected at runtime by `projectRepositoryFactory`.
- **`ProjectStore`**: the backend interface for the same operations, scoped by `userId`. One implementation: `SqliteProjectStore`.
- **Wire contract** (`packages/shared-types/projectContract.ts`): the type-only contract shared between frontend and backend, imported via the `@shared/*` alias. Holds `ProjectId`, `ProjectSourceKind`, `ProjectSyncState`, `LibraryFolder`, `LibraryPlacement`, `SavedProjectMeta`, `SectionPatch`, `ProjectPatch`. The two sides keep separate `ProjectSnapshot` definitions because the frontend models the rich domain (`LearningPlan`, `ProjectSource`, …) and the backend treats the payload as permissive JSON.
- **Persistence signature**: a string summarizing the snapshot, used to decide whether a save is needed. Two variants:
  - `buildPersistenceSignature(snapshot)`: full serialization including `source`. Used for content-equality (e.g. LAN transfer verification).
  - `buildAutosaveSignature(snapshot)`: skips `source` via a reference-identity token. Used in the autosave loop; avoids re-serializing the PDF on every render.
- **Persist queue**: the FIFO of granular PATCH operations (`enqueuePatch`, `flush`). Deduplicates by `key`, retries with exponential backoff. Used in LAN mode for highlight/note edits.
- **Sync state**: the observable `'saved' | 'saving' | 'error'` that drives the sync indicator. Auto-clears to `'saved'` after 2s as a safety net.
- **Snapshot hydration**: the load-time normalization performed by `prepareSnapshotForHydration` when a project is opened. Migrates legacy plan shapes, strips dropped fields, normalizes markdown, repairs annotations.
- **Reference-identity token**: an integer assigned to an immutable object (typically `source`) via `WeakMap` so the autosave loop can detect change without serializing the PDF.

## Reader

- **Reader**: the lesson-reading screen. One of the four `AppState` screens.
- **Reader state**: the visual-state hook (`useWorkspaceReaderState`) that composes focus mode, dark mode, sidebar state, audio state, quiz UI, settings panel, and preferred-models state. Holds no project data.
- **Reader actions**: the gesture-to-operation translator (`useWorkspaceReaderActions`). Calls the controller; does not decide validity.
- **Reader chrome**: the layout subset (focus, dark, sidebar, modules expansion, mobile viewport). Hook `useReaderChrome`.
- **Speech block**: a semantically meaningful chunk of lesson text, suitable as one TTS read-out unit. Produced by `useReaderSpeechBlocks`.
- **Speech chunk**: an audio segment generated by the TTS pipeline (~580 characters of text, ~35 ms crossfade between adjacent chunks). Managed by `useTtsPlayer`.
- **Context menu**: the menu shown when the user selects text inside a lesson. Drives highlight, sticky note, and Ask-AI actions.
- **Ask AI panel** (`ContextAnswerPanel`): the contextual chat overlay opened from the context menu. Uses Vercel AI SDK.

## Library

- **Library**: the home screen. Lists projects, organizes them in folders, and exposes the home chat.
- **Library tree** (`LibraryTree`): the folder hierarchy plus placement of projects within folders.
- **Folder** (`LibraryFolder`): a named container with `parentFolderId`, `order`, timestamps.
- **Placement** (`LibraryPlacement`): an entry that says "project X sits in folder Y at order Z". Reorderable via drag.
- **Library assistant**: the home chat agent. Uses Vercel AI SDK and can invoke library tools.
- **Library tool**: a tool the library assistant can invoke (`listLibraryTree`, `getProjectOverviews`, etc.). Implemented in `services/library/toolExecutor.ts`.

## Modes

- **Repository mode**: `'indexeddb' | 'lan'`. Selects which `ProjectRepository` adapter is active. Stored in `localStorage.projectRepositoryMode`; overridable by Vite/process env at first load.
- **LAN mode**: the configuration where the frontend talks to the backend SQLite store across a private network. Enables shared project access between devices on the same LAN.
- **Learn mode**: a project mode that runs without a source document. The user studies a topic chosen at assessment time, and the AI generates the plan from scratch. Flag: `domain.isLearnMode`.

## Disambiguation

- **section**: overloaded in the codebase.
  - In `activeSectionId`, `selectActiveSection`, `openSection`, `setActiveSection`: equivalent to **lesson**. The selectors return `LessonNode`. Exercises are addressed separately via `openExercise`.
  - In `SectionAnnotation`, `LearningSection`: the base shape that both `LessonNode` and (historically) other plan entries shared. Effectively the lesson schema.
  - In the backend `SectionPatch` type: the lesson update shape used by `patchProject`.
  - **Preferred new name**: `lesson` where the meaning is "a `LessonNode`", `pathNode` where it is "a lesson or exercise". `section` stays in identifiers already in use but should not be introduced in new code.

## Deprecated terms

These names appear in legacy storage payloads or transitional code. Do not use them in new code.

- **Laboratory**, **`LaboratoryState`**, **`LaboratoryExercise`**, **`activeLaboratoryExerciseId`**: superseded by **application exercises** as `PathNode` entries with `kind: 'exercise'`. Old snapshots loaded from storage may still carry these fields inside the raw JSON blob; they are stripped during hydration on the frontend and dropped from any inbound payload on the backend.
- **Mini-lab lesson**: a transitional lesson shape that lived between the laboratory removal and the application-exercise rollout. Removed at hydration time by `removeTemporaryMiniLabLessons`. Use **application exercise** instead.
- **`useWorkspaceReaderRuntime`**, **`WorkspaceReaderRuntime`**, **`readerRuntime`**: renamed to the **state** form (`useWorkspaceReaderState`, `WorkspaceReaderState`, `readerState`). Avoid "runtime" as a name for stateful objects in this codebase; it is reserved for things that are genuinely about execution time.
- **`resetRuntimeState`**: renamed to **`resetSessionState`** to match what it actually resets (the session slice of controller state).

## Example dialogue

> **Dev:** "If I want to add a new field to the lesson, where do I touch?"
> **Domain expert:** "Add it to `LessonNode` in `apps/web/types.ts`. The compiler will surface every place the domain reducer, the controller, the snapshot hydration, and the backend `SectionPatch` need to know about it. The backend `ProjectSnapshot` is defined independently, so update it too."

> **Dev:** "The Ask AI panel and the library chat — same pipeline?"
> **Domain expert:** "Same SDK (Vercel AI SDK), different backend routes (`/api/chat/context` vs `/api/chat/library`) and different tool sets. Both are distinct from the OpenRouter batch pipelines under `services/openrouter/`."

> **Dev:** "Is `LaboratoryState` still a thing?"
> **Domain expert:** "Only as a legacy field in inbound snapshots. The current model is application exercises living inside the learning plan as `PathNode` entries."
